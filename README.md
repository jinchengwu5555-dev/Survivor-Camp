## 第一次打开项目

1. **安装引擎**：到 Cocos 官网下载 **Cocos Dashboard**，在 Dashboard 的“安装”页里安装 **Cocos Creator 3.8.x**。
2. **下载代码**：推荐用 [GitHub Desktop](https://desktop.github.com/) 克隆本仓库，并切换到 `claude/game-dev-initial-planning-ghtbzn` 分支。
3. **导入项目**：Dashboard →“项目”→“添加”（或“导入”），选择仓库文件夹。如果提示引擎版本不同，选择“升级”并继续。
4. **设置分辨率**：菜单“项目”→“项目设置”→“项目数据”，把设计分辨率设为 **720 × 1280**，勾选“适配宽度”。
5. **创建主场景**（只需要做一次）：
   1. 在“资源管理器”的 `assets` 上右键 → 新建文件夹 `scenes`
   2. 在 `scenes` 上右键 → 新建 → Scene，命名为 `main`，双击打开
   3. 在“层级管理器”空白处右键 → 创建 → UI 组件 → **Canvas**
   4. 选中 Canvas，在“属性检查器”底部点“添加组件”，搜索 **GameRoot** 并添加
   5. `Ctrl + S` 保存场景
6. **预览**：点编辑器顶部的 ▶（选择“浏览器”预览）。能看到营地界面和开场事件“门外的呼救”就说明成功了。
7. 编辑器会生成很多 `.meta` 文件，**这些文件要一起提交到 Git**（它们记录了资源 ID，丢了场景就会坏）。

### 联网与排行榜

游戏**需要联网**：启动时检查网络，没网显示“需要联网”和重试按钮；玩的过程中断网，营地暂停（这段算离线），连上后继续（`platform/Network.ts`）。

排行榜比的是**最长存活天数**（天数只按在线时间算），有两个榜：

| 榜 | 怎么实现 | 代码 |
|---|---|---|
| 好友榜 | `wx.setUserCloudStorage` 写入成绩，开放数据域读好友数据画在 sharedCanvas 上，主域用 `SubContextView` 显示 | `platform/Leaderboard.ts`、`build-templates/wechatgame/openDataContext/index.js` |
| 全服榜 | 微信云开发的云函数，服务器按真实时间校验天数，改存档刷不上去 | `build-templates/wechatgame/cloudfunctions/leaderboard/` |

每过一个游戏日、切到后台、营地覆灭时各上报一次。

**开通全服榜（只需要做一次）：**

1. 微信开发者工具打开 `build/wechatgame`，点工具栏的“**云开发**”，开通（有免费额度），记下**环境 ID**。
2. 把环境 ID 填到 `assets/scripts/platform/Leaderboard.ts` 的 `CLOUD_ENV_ID`，重新构建。
3. 在 `build/wechatgame/project.config.json` 里加一行 `"cloudfunctionRoot": "cloudfunctions/",`，开发者工具里就会出现云函数目录。
4. 右键 `cloudfunctions/leaderboard` →“**上传并部署：云端安装依赖**”。
5. 云开发控制台 → 数据库 → 新建集合 **`leaderboard`**，权限选“仅创建者可读写”（客户端不直接读写，全部经过云函数）。

没填 `CLOUD_ENV_ID` 或者在编辑器里预览时，排行榜用调试实现（只显示自己）。

**防刷校验**（`rules.js`，有单元测试）：服务器记下第一次看到这一局的时间，之后上报的天数不能超过“这段真实时间里全程在线最多能玩出来的天数 × 1.2 + 2”，多出来的直接截掉。云函数的 `config.json` 要和 `balance.json` 的时钟参数一致，`npm test` 会检查。

### 事件写法示例

```json
{
    "id": "my_event",
    "title": "事件标题",
    "text": "事件描述",
    "weight": 5,
    "once": true,
    "conditions": { "minDay": 2, "hasSurvivors": ["toby"] },
    "choices": [
        {
            "text": "选项文字",
            "cost": { "food": 10 },
            "outcomes": [
                { "weight": 3, "text": "好结果", "effects": [ { "type": "addSurvivor", "survivor": "hank" } ] },
                { "weight": 1, "text": "坏结果", "effects": [ { "type": "injure", "survivor": "random" } ] }
            ]
        }
    ]
}
```

- `weight`：随机抽取权重，`0` 表示只能由剧情触发；`outcomes` 里的 `weight` 决定各种结果的概率。
- `speaker`（可选）：事件卡上显示谁的头像（幸存者 id）。不写就自动用正文里第一个提到的人，都没提到就显示“营地”旁白。
- 可用的效果（`effects`）：
  - `resource`：增减资源
  - `mood`：改心情（`target` 可以是某个幸存者 id、`random` 或 `all`）
  - `addSurvivor` / `removeSurvivor`：有人加入 / 离开
  - `injure` / `heal`：受伤 / 治疗
  - `flag`：记下一个剧情标记
  - `triggerEvent`：接着触发另一个事件
  - `addWanderer`：随机生成一个流浪者加入（可以写 `specialty` 指定专长）
  - `discoverSite`：发现一个新的营地地点（`site` 写 sites.json 里的 id）
  - `stat`：累计一项统计数据（`amount` 默认 1），成就和悬赏都读统计。现有的：`diary_pages`（日记残页）、`quiet_moments`（宁静时刻）、`laughs`（欢笑）
- 可用的条件（`conditions`）：`minDay`、`minSurvivors`、`flags`、`notFlags`、`hasSurvivors`。

## 战斗系统

战斗是自动进行的横版对战，玩家可以手动释放每个角色的 1 个主动技能。代码在 `assets/scripts/core/battle/`，分成 5 个模块：

| 模块 | 文件 | 配置表 | 负责什么 |
|---|---|---|---|
| 1. 角色配置 | `units.ts` | `units.json` | 基础属性、外观、等级成长，生成战斗角色 |
| 2. 技能系统 | `skills.ts` | `skills.json` | 触发条件、目标选择、冷却、效果执行 |
| 3. 技能编排登记表 | `registry.ts` | — | 统一登记角色 / 技能 / 状态，检查配置错误，生成技能说明，调试时临时改数值 |
| 4. 伤害结算管线 | `damage.ts` | — | 增伤 → 暴击 → 防御减免 → 易伤 → 取整 → 护盾 → 扣血 |
| 5. 控制和状态 | `status.ts` + `Battle.ts` | `statuses.json` | 眩晕 / 定身 / 沉默、增减益、持续伤害、护盾；移动、索敌、普攻、刷怪、胜负判定 |

### 查看一场战斗的战报

```bash
npm run battle
```

会打印一场“五人小队 vs 尸群”的完整中文战报，改完数值后用它看效果。

### 数值平衡报告

```bash
npm run balance
```

每个探索地点、每种尸潮在不同的训练场 / 路障等级下各打 50 场，打印胜率和平均受伤人数。调整 `units.json`、`locations.json`、`raids.json` 之后跑一下，确认难度曲线是“越练越强、路障越高越稳”。

### 经济节奏报告

```bash
npm run economy
```

模拟一个“最低投入”的普通玩家玩 60 天真实时间：每天 8:00～22:00 每 2 小时上线一次，每次 5 分钟（游戏时间只在这 40 分钟里走），不看广告、不做物品、不接悬赏。报告按天打印游戏天数、指挥部等级、资源、士气、守夜战绩、尸潮加成（喘息值）、死亡人数和成就数，最后列出死因。调整任何经济数值后都应该跑一下，对照下面的目标曲线。

### 战斗在营地里怎么发生

- **探索**：在“探索”页派出小队（自动挑战斗力最高的 4 个人）。小队出发后离开工作岗位，到时间自动打一场战斗：
  - 打赢：带回战利品，并解锁下一个地点
  - 打输：什么都拿不到
  - 战斗中倒下的人会**受伤**（`injuryRecoveryMinutes` 游戏分钟，约 5 分钟在线），可以用药品在医务室立即治好
  - 打赢后这个地点要过一个游戏日（`locationRestockMinutes`）物资才重新聚起来，才能再去
  - 看激励视频可以让小队立即返回
- **尸潮夜袭**：第 1 集结束后约 1 分钟来第一次（`firstRaidMinutes`），之后每个游戏日来一次，天数越往后尸潮越凶。
  - 所有能战斗的人和**路障**一起上阵，大家守在路障后面，路障生命 = 安全值 × 30
  - 撑到时间结束就算守住；**路障被拆就算失败**，会损失 10% 物资
  - 离线时营地暂停，不会有尸潮
- **训练场**：每升一级，所有幸存者的战斗等级 +1。
- 探索的战斗自动结算（手动技能自动释放）。每场战斗的参数和玩家的操作都存进了战报，“战报”页可以**回放**，结果完全一致。

### 亲手守夜（`core/liveRaid.ts` + `ui/BattleView.ts`）

界面开着时（`camp.liveRaids = true`），尸潮来了不会自动结算，而是放进 `state.pendingRaid`，界面切到战斗画面，实时演出：

- 每个有主动技能的角色一个按钮，冷却好了会亮起“点我！”。默认要玩家自己点，也可以打开“自动技能”。
- **修补路障**：花木材给路障回血，每次回 20% 生命，花费 = 回的生命 × 0.1（至少 10 木材），每场最多 3 次（`balance.raidRepair`）。
- 可以 2 倍速，也可以“跳过”（剩下的自动打完）。
- 战斗中关掉游戏：下次打开会从头再打这一场（同一个种子）。
- 测试和数值模拟里 `liveRaids = false`，照旧自动结算；没有界面在看时留着的尸潮也会自动打完。
- 所有操作记在 `BattleSetup.inputs` 里（放技能、切自动、修路障），战报回放时原样执行。

实测（`horde` / `great_horde`，5 人）：营地弱的时候，大尸潮完全不按技能必输、及时按技能必赢——按不按技能在关键时刻差别很大。

### 路边拾荒（`core/pickups.ts`）

营地附近平均每 10 游戏分钟（约 75 秒在线）出现一样东西——补给箱、废铁堆、急救箱、落单的行尸、罐头——显示成屏幕上方的金色按钮，点一下就捡走。最多同时 3 个，60 游戏分钟没人捡就消失。奖励随指挥部等级按探索战利品的倍率成长（罐头不成长）。配置在 `pickups.json`。

### 每日目标（`core/daily.ts`）

每个游戏日（在线约 10 分钟）从 `daily.json` 的任务池里抽 3 个小目标（同一种统计只抽一个），比如“消灭 15 只丧尸”“探索成功 1 次”“在营地附近捡 3 样东西”。完成后在“任务”页领奖励，3 个都领完再开一个宝箱。没领的第二天就没了。有东西可领时，“任务”页签会显示 ❗。

- 进度用统计数据判断（抽到时记下当前值），和悬赏一样。
- `conditions` 不满足、`requiresBuilding` 还没建的目标不会抽到（比如没开始守夜就不会抽到“守住 1 次尸潮”）。

实测：`npm run economy` 的模拟玩家顺手捡东西、领每日目标，经济曲线基本不变——它们是让等待时有事可做，不是主要收入。

### 安排工作（`core/workers.ts`）

- 建筑详情里可以“＋ 派一个人来”（优先专长对口的）/“－ 撤下一人”（优先不对口的）。
- “幸存者”页的“一键安排工作”：食物在减少就先派去厨房，否则先去废料场，再是医务室；专长对口的人优先去自己的建筑。

### 新手引导（`core/guide.ts`）

不用单独写引导脚本：根据当前剧情集的第一个未完成目标，算出“下一步”，界面顶部显示提示条，并把要点的页签、建筑、按钮高亮成金色（带 👉）。

- 开局没人干活 → 高亮“幸存者”页的“一键安排工作”
- 升级建筑 → 高亮对应建筑；需要先升指挥部就指向指挥部；正在升级就指向“看广告加速”
- 搜刮地点 → 高亮“探索”页对应地点的“派出小队”
- 第 1 集结束后提示“尸潮就要来了”

### 技能写法

```json
{
    "id": "molotov",
    "name": "燃烧瓶",
    "description": "德里克扔出燃烧瓶，点燃一片敌人。",
    "trigger": { "type": "active" },
    "cooldown": 15,
    "targeting": { "rule": "nearestEnemy", "radius": 2 },
    "effects": [
        { "type": "damage", "ratio": 1.2, "damageType": "fire" },
        { "type": "status", "status": "burn", "duration": 4, "power": 0.3 }
    ]
}
```

- **触发方式 `trigger.type`**：`active` 手动释放、`auto` 冷却好了自动释放、`onAttack` 普攻时按 `chance` 概率触发、`battleStart` 开战时触发、`hpBelow` 生命低于 `ratio` 时触发一次、`onDeath` 死亡时触发。每个角色最多 1 个 `active` 技能。
- **目标 `targeting.rule`**：`self`、`currentTarget`、`nearestEnemy`、`randomEnemy`、`lowestHpAlly`、`allAllies`、`allEnemies`；加上 `radius` 就变成范围技能（主目标周围 N 格内的同阵营单位都会被命中）。
- **效果 `effects`**：
  - `damage`：伤害 = `ratio` × 攻击力，`damageType` 可选 `physical` / `fire` / `poison` / `true`
  - `heal`：治疗 = `ratio` × 攻击力
  - `status`：施加状态，持续 `duration` 秒；持续伤害和护盾的强度 = `power` × 攻击力
- **伤害类型**：物理受全额防御减免，火焰受一半，毒素和真实伤害无视防御。防御公式：减伤 = 防御 / (防御 + 100)。

## 营地生活系统

### 季节与过冬

季节按“存活天数”循环：夏 3 天 → 秋 3 天 → 冬 3 天 → 春 3 天。
- **夏**：食物坏得快（腐烂 ×1.5）。
- **秋**：厨房产量 ×1.2，适合囤粮囤柴。
- **冬**：厨房产量减半、腐烂变慢；每人每分钟烧 0.08 木材取暖，没柴会挨冻（心情下降）。第一次入冬触发事件“第一场雪”。
- **春**：一切恢复正常，熬过冬天会记入成就。

### 食物腐烂

新鲜食物每分钟坏掉 0.1%（乘以季节倍率），囤得越多坏得越多。**罐头永不过期**。建造**地窖**可以让食物坏得慢 30% / 50% / 70%。

### 工坊

建造工坊后可以制作燃烧瓶、急救包，2 级工坊可以制作钉子炸弹。物品在探索和守夜时自动分给上阵的人，**在战斗中真的用掉了才扣库存**。燃烧瓶和急救包都要用药品（酒精），需要取舍。

### 尸潮：血月夜和营地的狗

- **血月夜**：每第 4 次尸潮是血月夜，尸群多一半，守住后奖励翻倍。顶部会提前预警。
- **营地的狗**：通过事件“跟回来的狗”收养后，守夜时会一起上阵，还会咬住行尸拖慢它们。
- **钢板路障**：路障新增第 4 级，是应对血月大尸潮的后期目标。

### 悬赏板

在“悬赏”页接取，最多同时 3 个。完成后领取奖励和猎人经验，猎人等级分为见习猎人、猎人、老练猎人、传奇猎人，等级越高能接的悬赏越难。悬赏目标用统计数据表示，比如 `kill_walker`（击杀行尸数）、`clear_clinic`（清理卫生所次数）、`raids_won`（守夜胜利次数），接取之后再增加指定数量就算完成。

### 成就

24 个成就，奖励罐头。条件和剧情目标用同一套写法（`buildingLevel` / `resource` / `flag` / `survivors` / `stat` / `day`），解锁时会弹出提示。`hidden: true` 的成就解锁前显示为“？？？”。

### 统计数据

游戏会自动累计这些统计，成就和悬赏可以直接使用：

| 统计 | 含义 |
|---|---|
| `zombies_killed`、`kill_<丧尸 id>` | 击杀数 |
| `expeditions_won` / `expeditions_lost`、`clear_<地点 id>` | 探索结果 |
| `raids_won` / `raids_lost`、`blood_moons_won` | 守夜结果 |
| `items_crafted`、`craft_<物品 id>`、`use_<物品 id>` | 制作 / 使用物品 |
| `bounties_completed`、`treated`、`recruited`、`events_resolved`、`winters_survived` | 其他 |
| `deaths`、`death_<死因>`、`wanderers_joined`、`relocations`、`sites_discovered` | 人员和营地 |
| `offline_rewards` | 领到离线挂机收益的次数 |
| `barricade_repairs` | 守夜时修补路障的次数 |
| `upgrades` | 开始建筑升级的次数 |
| `pickups_collected` | 在营地附近捡东西的次数 |
| `daily_completed`、`daily_chests` | 完成每日目标 / 打开每日宝箱的次数 |

## 无限流经济

目标是长期游玩：没有“升满”的一天，尸潮压力持续上涨，但不会让玩家陷入必输的死循环。

### 时间：只算在线时间

- **游戏时间只在在线时走**（`core/clock.ts`）：1 秒在线 = 8 秒游戏时间（`balance.clock.onlineTimeScale`）。游戏里的一天是 80 游戏分钟（`dayLengthMinutes`），也就是**在线约 10 分钟过一天**。
- 界面每秒调用一次 `camp.online(Date.now())`。两次调用间隔超过 15 秒（`clock.onlineGapSeconds`）就算离线：切后台、关游戏、断网都算。
- **离线时营地暂停**：不吃饭、不守夜、不死人，建造 / 探索 / 养伤的计时也停住。
- **离线挂机收益**（`core/offline.ts`）：回来时按当前工人的产量发一小笔食物、木材、零件——离线 1 分钟 = 0.25 游戏分钟的产量，最多算 8 小时，不足 5 分钟不发（`balance.offline`）。8 小时离线大约相当于半天的产量。
- 改手机时间没用：往前拨只会被当成离线；往回拨再拨回来，拿不到重复的离线收益（`clock.maxRealAt`）。
- 所以**存活天数 = 在线时长**，排行榜比的就是谁在线撑得久。界面上的倒计时都换算成在线的真实秒数（`realSeconds()`）。
- core 里所有的 `now` 都是游戏时间，界面上的操作用 `camp.now`，不要传 `Date.now()`。
- 尸潮每个游戏日一次；季节、新手保护期、剧情里的“第 N 天”都按游戏日算。

### 建筑无限成长

`buildings.json` 里前几级手写（新手期可以精调），之后用 `scaling` 公式自动生成到 `maxLevel`：

```json
"scaling": { "maxLevel": 25, "costGrowth": 1.5, "timeGrowth": 1.32, "productionGrowth": 1.1, "slotsEvery": 3 }
```

- 每一级的花费 ×1.5、时间 ×1.32、产量 ×1.1，越往后升级越难，但永远有下一级。
- 生成的等级要求指挥部达到同样的等级（建筑不能超过指挥部）。
- 指挥部的仓库容量每级 ×1.6，比花费增长得快。**配置检查会自动发现“仓库存满也不够升级”的死局**，`npm test` 会报错。
- 游戏启动和测试都会先调用 `expandConfig()` 展开公式，其他代码只看展开后的 `levels`。

### 无尽尸潮与喘息

- 从第 24 天开始，每过 6 天所有尸潮丧尸 +1 级，奖励 ×1.15（指数增长），尸潮名称后面会显示“+N”。
- **喘息机制**：守夜失败一次，之后尸潮加成 -2；每守住一次恢复 1。打得过的玩家面对的威胁会一直上涨，被打趴的玩家有机会缓过来。
- 统计 `best_raid_level` 记录守住过的最高加成，可以作为排行榜指标（成就：尸潮渐涨 / 屹立不倒 / 末日灯塔）。
- 守夜失败损失 10% 物资（不含罐头）。

### 探索随营地成长

指挥部每高一级，探索的敌人 +0.5 级（向下取整），战利品 ×1.25。

### 看广告加速

每看一次，剩余建造时间减少 25%（至少 30 游戏分钟，约 4 分钟在线），短的升级直接完成。后期升级要很多个游戏日，一次广告不会直接完成。

### 目标曲线（`npm run economy` 的最低投入玩家）

模拟玩家每天上线 8 次、每次 5 分钟（一天在线 40 分钟 ≈ 4 个游戏日）。

| 真实天数 | 1 | 2 | 7 | 14 | 21 | 30 | 45 | 60 |
|---|---|---|---|---|---|---|---|---|
| 游戏天数 | 5 | 9 | 29 | 57 | 85 | 121 | 181 | 241 |
| 指挥部等级 | 3 | 5 | 9 | 11 | 13 | 14 | 16 | 17 |

- 从不断粮。
- 前 30 个游戏日（真实一周左右）几乎不死人。
- 第 80～100 个游戏日开始守夜失败，喘息机制把尸潮稳定在玩家能勉强应付的水平，之后每个游戏日平均死 0.3 人左右，靠流浪者补充。
- 营地等级大约能扛住 2 倍于自身等级的尸潮加成（见 `npm run balance` 的“无尽尸潮”表）。

## 生存竞赛：死亡、覆灭与换营地

**游戏比的是存活天数。** 人会死，营地会覆灭，也可以举营搬迁。

### 死亡

| 怎么死 | 说明 | 配置 |
|---|---|---|
| 战斗中倒下 | 30% 概率牺牲，否则重伤。医务室每级降低 3%（最多 70%），卫生所营地再减半。**探索打赢时倒下的人只会受伤**（队友会背回来） | `deathChanceOnFall`、`deathReductionPerInfirmaryLevel` |
| 守夜失败 | 尸群冲进营地，1 人被咬死（优先不是核心角色的人） | `raidBreachDeaths` |
| 饥寒 | 连续挨饿或挨冻累计 2 个游戏日（约 20 分钟在线）死 1 人，吃饱穿暖后重新计时 | `hardshipDeathMinutes` |
| 事件 | `removeSurvivor` 让人离开营地 | — |

- 前 6 个游戏日（约 1 小时在线）是**新手保护期**，不会死人（`deathGraceDays`）。
- 核心角色也会死。死者会记下剧情标记 `dead_<id>`，事件可以用 `notFlags` 避开已经死去的人。
- **流浪者**会通过事件投奔，探索打赢时也有概率救回一个（地点的 `recruitChance`）。他们的名字、职业、性格随机生成（`wanderers.json`），用“幸存者”角色战斗，专长对口同样有加成。
- 代码里查幸存者资料一律用 `survivorInfo()`（流浪者不在 `survivors.json` 里）。

### 营地覆灭

所有人都死了就是覆灭，时间停止，界面显示本局战绩和历史纪录，然后可以建立新的营地。**跨局保留**（单独存档 `doomsday-camp-records`）：最长存活天数、局数、累计天数、最近 10 局的战绩、已解锁的成就（新的一局不会重复发成就奖励）。

### 换营地

| 营地 | 怎么发现 | 优点 | 缺点 |
|---|---|---|---|
| 🏪 枫谷超市 | 开局 | 什么都有一点 | 没什么特别 |
| ⛽ 镇口加油站 | 打下加油站便利店 | 零件 +40%，每分钟自产零件 | 安全值 -40% |
| 🌾 河谷农场 | 打下五金店 | 食物 +60%，每分钟自产食物 | 安全值 -25%，食物坏得快 |
| 🏥 镇卫生所 | 打下镇卫生所 | 药品翻倍，伤好得快一倍，战死概率减半 | 尸潮 +2 级 |
| 🚓 警长办公室 | 打下警长办公室 | 安全值 +40%，战斗等级 +2 | 食物 -20% |
| 🏞️ 北岭水坝 | 日记第 4 页 | 安全值翻倍，尸潮 -3 级，床位 +6，每分钟自产食物 | 木材 -30%，路上最危险 |

搬迁的代价：
- 每人路上吃 20 食物。
- 所有能战斗的人都要打一场伏击战，倒下的人可能牺牲。
- 只能带走一半物资（罐头、工坊物品全部带走）。
- 路障等级按新地点的 `wallRetention` 保留，但不低于新地点自带的 `minWallLevel`。其他建筑保留。
- 搬完 3 天内不能再搬。
- 到达北岭水坝时，如果伊森还活着，会触发和莉莉的重逢。

### 普通玩家能活多久（`npm run economy`）

最低投入的模拟玩家（每天在线 40 分钟）：前 30 个游戏日几乎没有人死亡；第 80～100 个游戏日起守夜开始出现败仗，陆续有人牺牲，靠流浪者补充人手；60 个真实日（约 240 个游戏日）后仍然存活，但尸潮加成一直在涨。看广告加速、做物品、选对营地的玩家能活得更久。
